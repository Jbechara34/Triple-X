Sends your payout address to the public P2Pool Observer service over clearnet. Off by default.
Hide the Logs tab from the navigation if you don't need it day-to-day. On by default.
Lets this dashboard stop monerod, pull a pre-synced blockchain from another machine over SSH, and restart it - skipping a full network sync on a new install. Discord Notifications
Get pinged in a Discord channel whenever a block is found. In Discord: Server Settings → Integrations → Webhooks → New Webhook, then copy its URL and paste it below. Leave this blank to keep notifications off - nothing is ever sent without a URL saved here.
Every share you find counts toward your next PPLNS payout - but shares happen far more often than blocks, so this can be noisy. Off by default.
Which Pool Type Should I Use?
The hashrate brackets below are a rule of thumb, not a fixed rule - the actual "worth switching" point moves with how much total hashrate each P2Pool chain has at any given time. For an exact, live answer, use P2Pool's own Average Share Time Calculator. The PPLNS payout window lengths, on the other hand, are fixed by the protocol and don't change.
Pool TypeRule-of-thumb HashratePPLNS Payout Window
NanoUnder ~5 kH/s~18 hours
Mini~5 kH/s - 40 kH/s~6 hours
Standard (Main Chain)Over ~40 kH/s~6 hours
Lower hashrate on a busier chain means longer waits between shares - each share needs the pool to then find a Monero block before it pays out. If shares are regularly taking more than a day to find, switch to a smaller chain (Mini or Nano) for steadier, more frequent (if smaller) payouts.
P2Pool Memory Usage
Optional flags that reduce P2Pool's memory footprint. Each takes effect within a few seconds of saving, no restart needed. All off by default - P2Pool's normal behavior is unchanged unless you enable one.
Skips building RandomX's ~2GB lookup table, cutting P2Pool's memory use to roughly 0.6GB. The only cost is slower verification of shares submitted by other miners on the P2Pool network - negligible for a home node, especially on Mini/Nano pools.
Disables P2Pool's internal RandomX hasher entirely and asks monerod over RPC to verify each share instead. Only safe when monerod is local or on a fast LAN - true here, since monerod runs alongside P2Pool in this same stack. Makes --light-mode redundant if both are enabled.
Disables P2Pool's local chain-state cache. Saves a small amount of memory/disk, but P2Pool will resync more slowly from peers after every restart.
Combining --no-randomx and --no-cache brings memory use under 100MB.
Import Blockchain
This stops monerod, copies data from the machine/path you specify below into its data directory, fixes ownership, and restarts it. Point this at a pre-synced monerod data directory (the folder containing lmdb/) on another machine you control - anything else will not work and may need to be cleaned up manually afterward.
Instructions
This dashboard connects out to the other machine to pull the data (rather than that machine pushing to it), so that machine needs an SSH server running and reachable on your local network - not just an SSH client. You only need this on your LAN; there's no need to forward SSH to the internet or expose it publicly for this to work.
  1. Enable an SSH server on the other machine (the one with the already-synced blockchain), if it doesn't already have one running:
    • Windows doesn't have this on by default - having used scp/pscp before only means you have the SSH client. To also accept incoming connections: Settings → Apps → Optional Features → Add a feature → install OpenSSH Server, then open a PowerShell window as Administrator and run Start-Service sshd (and, so it starts automatically next time, Set-Service -Name sshd -StartupType Automatic).
    • Linux usually just needs it enabled if it's already installed: sudo systemctl enable --now ssh (Debian/Ubuntu) or sudo systemctl enable --now sshd (Fedora/RHEL/Arch).
    • macOS: System Settings → General → Sharing → turn on Remote Login.
    Use whatever username/password (or SSH key) you'd normally use to log into that machine - this dashboard doesn't create a separate account for it.
  2. Find that machine's monerod data directory - the folder that directly contains an lmdb subfolder (e.g. ~/.bitmonero on Linux, or wherever you pointed --data-dir).
  3. Make sure monerod is stopped on that other machine before starting the transfer - copying files out of a running node's data directory can grab an inconsistent snapshot.
  4. Fill in the Host/Port/Username fields below and choose SSH private key (recommended - your password is never sent) or Password authentication, providing the matching key/password.
  5. For Remote Path, either type the full path from step 2 directly, or click Browse... to click through that machine's actual folders instead - it connects with the Host/Username/auth details you just filled in and lets you navigate to the right folder visually.
  6. Click Start Import and confirm. This node's monerod will stop, the data will copy over the network (this can take from minutes to hours depending on size and connection speed), and monerod will restart automatically when it's done. You can navigate away - the transfer keeps running on the server and this page will pick the progress back up when you return.
Never saved to disk beyond the single import - deleted the moment the transfer finishes or fails.
